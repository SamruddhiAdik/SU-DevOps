# Stakeholder User Personas and Matrix

## User personas

### Aarav — Student
**Objectives:** Find academic references quickly and avoid late fines.  
**Pain points:** Long queues and unexpected fine accumulation.  
**Target features:** Mobile-friendly search, availability status, and due-date alerts.

### Mrs. Sunita — Librarian
**Objectives:** Process checkouts quickly and maintain accurate catalog inventory.  
**Pain points:** Manual record entry, stock discrepancies, and lost books.  
**Target features:** Checkout/return interface, inventory updates, and fine tracking.

### Dr. Verma — Library Administrator
**Objectives:** Monitor library utilization and produce departmental reports.  
**Pain points:** Limited real-time usage data and slow manual report generation.  
**Target features:** Administrative dashboard and report export.

## Stakeholder matrix

| Stakeholder group | Responsibilities and expectations |
|---|---|
| Business stakeholders: college management, library administration, students, faculty | Define the business vision, validate usability, and confirm library rules. |
| Engineering stakeholders: developers, UX designers, QA engineers | Design the architecture, build the interface and services, test behavior, and maintain quality. |
| Operations stakeholders: DevOps, database administrators, security team | Maintain infrastructure, database integrity, deployment automation, and security. |
